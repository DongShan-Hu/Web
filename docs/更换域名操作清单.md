# 更换域名操作清单

项目原先有 4 处硬编码域名，容易漏改。现已改为**唯一配置源**：改一个文件，其余自动生成。

| 作用 | 文件 | 是否手工编辑 |
| --- | --- | --- |
| 唯一配置源 | `deploy/domain.env` | **是，只改这里** |
| 生成 Nginx 配置 | `deploy/nginx.conf` | 否，脚本覆盖 |
| 生成前端配置 | `public/config.js` | 否，脚本覆盖 |
| 生成脚本 | `deploy/apply-domain.sh` | 否 |

## 一、当前状态

服务器公网 IP `134.195.211.122`，**位于美国，不需要 ICP 备案**。当前借用 sslip.io 免备案临时域名：

```text
http://134.195.211.122.sslip.io/              主站
http://zhang-hong.134.195.211.122.sslip.io/   张红作品集
```

`deploy/domain.env` 当前值：

```sh
PRIMARY_DOMAIN="134.195.211.122.sslip.io"
SERVER_IP="134.195.211.122"
EXTRA_DOMAINS=""
PUBLIC_SCHEME="http"
SSL_CERT_PATH=""
SSL_KEY_PATH=""
```

## 二、切换步骤

### 1. 本地改配置

编辑 `deploy/domain.env`：

```sh
PRIMARY_DOMAIN="你的域名.com"
SERVER_IP="134.195.211.122"
EXTRA_DOMAINS="www.你的域名.com"
PUBLIC_SCHEME="http"        # 证书签发成功后再改 https
```

### 2. 生成并预览

```sh
bash deploy/apply-domain.sh
```

脚本会打印新地址。确认 `deploy/nginx.conf` 与 `public/config.js` 的内容符合预期。

### 3. 本地检查

```sh
npm run check
```

### 4. 提交推送

```sh
git add -A
git commit -m "切换到正式域名"
git push
```

### 5. 配置 DNS

在域名解析后台添加 A 记录：

| 主机记录 | 类型 | 值 |
| --- | --- | --- |
| `@` | A | `134.195.211.122` |
| `www` | A | `134.195.211.122` |
| `*` | A | `134.195.211.122` |

`*` 是客户子域名的泛解析，缺了它客户站全部 404。

### 6. 服务器更新

```sh
cd /home/dongshan/workspace/Web
git status --short                     # 应为空
git pull --ff-only origin main
sudo bash deploy/install-nginx-ubuntu.sh
```

`install-nginx-ubuntu.sh` 会先调用 `apply-domain.sh` 重新生成配置，再检查语法并重载。**不会重复安装 Nginx**。

### 7. 验证

```sh
curl -I http://你的域名.com/
curl -I http://zhang-hong.你的域名.com/
curl -I http://不存在的名字.你的域名.com/    # 应为 404
```

DNS 生效需要几分钟到几小时，`curl` 报域名解析失败就是还没生效，不是配置问题。

## 三、加密 HTTPS

DNS 生效后执行：

```sh
apt install -y certbot python3-certbot-nginx
certbot --nginx -d 你的域名.com -d "*.你的域名.com" \
  --preferred-challenges dns-01
```

泛域名证书只能用 DNS 验证。签完后按提示在 DNS 后台添加 TXT 记录。

拿到证书后，把 `deploy/domain.env` 的 `PUBLIC_SCHEME` 改为 `https`，重新生成并部署：

```sh
bash deploy/apply-domain.sh
git add -A && git commit -m "启用 HTTPS" && git push
# 服务器上
git pull --ff-only origin main && sudo bash deploy/install-nginx-ubuntu.sh
```

自动续期由 certbot 的 systemd timer 负责，用 `systemctl list-timers | grep certbot` 确认。

## 四、换域名的影响面

| 影响对象 | 是否需要处理 |
| --- | --- |
| 客户站文件与图片路径 | **不需要**。全部使用相对路径 |
| `public/sites.json` | **不需要**。目录用 slug，与域名无关 |
| 已发出的旧链接 | 失效。前期客户少，逐个通知即可 |
| 客户已生成但未扫描的二维码 | 需重新生成 |
| 小红书已发布内容里的链接 | 平台通常不允许外链，影响小 |

## 五、回退

改回 `deploy/domain.env` 的 `PRIMARY_DOMAIN`，重新执行第 2、4、6 步即可。旧域名的 DNS 记录建议保留一段时间再删。
