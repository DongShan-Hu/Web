# 工程目录说明

## 当前唯一主工程

`Web/` 是当前主工程，负责多站点入口、客户站点、模板、检查、构建和部署。

```text
Web/
├─ public/                         # 唯一对外发布目录
│  ├─ index.html                   # 多站点主入口
│  ├─ sites.json                   # 站点登记
│  └─ sites/
│     └─ zhang-hong/               # 张红个人站点
├─ templates/                      # 新站点起步模板，不直接发布
│  ├─ resume/
│  ├─ engineering/
│  └─ company/
├─ scripts/                        # 预览、检查、构建、添加站点
├─ deploy/                         # Nginx 与服务器部署
└─ docs/                           # 部署与维护说明
```

## 张红站点

张红的对外页面统一放在：

```text
Web/public/sites/zhang-hong/
```

该目录内包含首页、文字简历、样式、脚本、图片、视频和 PDF。后续修改张红网页时，优先修改这里，不要直接修改外层的 `portfolio-2026/`。

## 其他目录的职责

### `Web-platform/`

这是同一 GitHub 仓库的旧版本副本。当前不作为主工程使用，暂不删除或移动，避免影响历史部署和回退。

### `portfolio-2026/`

这是张红作品集的独立源文件/设计工作区，保留用于素材整理、视觉迭代和本地检查。它不是当前多站点部署根目录。

### `.portfolio-build/`

张红作品集的生成与检查脚本，服务于 `portfolio-2026/`。

### 根目录素材与压缩包

根目录下的 PPT、ZIP 和原始作品素材属于归档/源素材，不直接参与 `Web` 的线上发布。

## 后续新增站点规则

以后新增客户或展示页时：

1. 在 `Web/public/sites/` 下建立一个小写英文 slug 目录；
2. 站点首页使用 `index.html`；
3. 图片、视频和样式放在该站点自己的目录内；
4. 在 `Web/public/sites.json` 中登记；
5. 先运行 `npm run check`，再构建和部署。

示例：

```text
Web/public/sites/
├─ zhang-hong/
├─ client-a/
└─ client-b/
```

## 当前整理原则

- 不改现有业务代码和部署路径；
- 不删除重复工程和历史素材；
- `Web` 作为唯一主工程继续维护；
- 后续如需归档 `Web-platform/`，先确认没有服务器或外部脚本仍在使用它。
