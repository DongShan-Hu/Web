# 自有服务器部署指南

当前服务器为 Ubuntu 22.04，公网 IP 为 `134.195.211.122`。客户使用独立子域名，暂借用 [sslip.io 公共 DNS](https://nip.io/)，不需要先买域名。下列命令在**服务器终端**执行，本机预览在 Windows 项目目录执行。

```text
http://134.195.211.122.sslip.io/              主站
http://客户名称.134.195.211.122.sslip.io/     后续客户
```

这些是部署完成后的地址。当前版本尚未收录客户内容；主站部署后可以访问，客户子域名需添加对应目录后才有页面。DNS 解析到服务器不代表网站已经上线。

## 1. 确认服务器状态

在云平台控制台打开远程终端，或在自己的终端通过 SSH 登录。先执行：

```sh
cat /etc/os-release
uname -m
command -v docker
command -v nginx
sudo ss -lntp | grep -E ':(80|443|8080)\b' || true
```

记录公网 IP、系统版本、所在地区、是否安装宝塔和是否已有网站。不要把密码、私钥或 GitHub 令牌写进仓库。

## 2A. 已安装 Docker 的服务器

Docker Compose 需要 `docker compose version` 可以正常运行。系统中没有 Docker 时，先按实际发行版安装；Ubuntu 22.04/24.04/26.04 可参照 [Docker 官方 Ubuntu 安装文档](https://docs.docker.com/engine/install/ubuntu/)。已有容器运行时先检查版本与冲突，不重复安装。

选择自己的工作目录，不覆盖已有项目：

```sh
git clone https://github.com/DongShan-Hu/Web.git
cd Web
cp .env.example .env
sudo docker compose version
sudo docker compose config
sudo docker compose up -d --build
sudo docker compose ps
curl -f http://127.0.0.1/healthz
```

仓库是公开仓库，克隆不需要 GitHub 密码。若服务器不能连接 GitHub，可在 GitHub 下载源码 ZIP 并上传、解压后进入项目目录；不需要改动服务器网络设置来完成部署。

80 被占用时，编辑 `.env` 改为 `WEB_PORT=8080` 后再启动，访问 `http://公网IP:8080/`。若通过现有宝塔/Nginx 反向代理，设为：

```dotenv
WEB_BIND_IP=127.0.0.1
WEB_PORT=8080
```

再把现有网站的代理目标设置为 `http://127.0.0.1:8080`。此时客户端访问现有网站端口，不需要将 8080 开放到公网。

Nginx 镜像固定为官方 `1.30.4-alpine`，源码与配置被构建进镜像。[官方镜像说明](https://hub.docker.com/_/nginx)

## 2B. 宝塔静态网站

1. 在宝塔中新建主站，域名填 `134.195.211.122.sslip.io`，根目录对应本项目 `public/`。
2. 将本项目 **`public/` 内的内容** 上传到网站根目录；不要上传整个仓库或原始素材目录。
3. 每个客户另建静态站，域名例如 `acme.134.195.211.122.sslip.io`，根目录直接对应 `public/sites/acme/`。首页设为 `index.html`，保持图片与视频相对路径；纯静态网站不要添加 PHP 或 SPA 的全路径首页回退。
4. 启用 Nginx 静态服务，并配置 404 页面为根目录的 `404.html`。确认 MP4/PDF/WebP 的 MIME 类型正常。
5. 在云平台安全组和面板防火墙放行实际网站端口。

模板、文档、`.git/` 和 `.env` 不应放到网站根目录。客户子域名直接从 `/` 打开客户首页。

## 2C. 原生 Nginx

适用于希望不用 Docker 的 Linux 服务器。安装 Nginx 的命令取决于发行版，例如 Ubuntu/Debian：

```sh
sudo apt update
sudo apt install nginx git
```

在当前 Ubuntu 服务器推荐执行：

```sh
git clone https://github.com/DongShan-Hu/Web.git /opt/dongshan-web
cd /opt/dongshan-web
bash deploy/install-nginx-ubuntu.sh
```

当前以 root 登录，无需额外 sudo。普通用户使用 sudo 克隆到 `/opt/` 并执行安装脚本。已有 `/opt/dongshan-web` 时先核对目录，不重复克隆或覆盖。

脚本会将 Nginx 配置写到 `/etc/nginx/conf.d/dongshan-web.conf`，通过 Host 区分主站与客户子域名；例如 `acme` 对应 `public/sites/acme/`。新增客户只需添加相应目录，不需要重复添加 Nginx 配置。脚本保留其他网站与 Ubuntu 默认配置，已有本项目配置会先备份。

手动接入时，以 `deploy/nginx.conf` 为起点，将所有 `/usr/share/nginx/html` 替换为实际 `public/` 的绝对路径。该文件包含 `map`，必须 include 在 Nginx 的 `http {}` 上下文中，不能直接粘贴进宝塔现有的 `server {}`。

```sh
sudo nginx -t
sudo systemctl reload nginx
```

只有语法检查通过才重载。Nginx 原生静态服务支持 MP4 Range 请求，不需要代理到 Node 服务。[Nginx 官方文档](https://nginx.org/en/docs/http/ngx_http_core_module.html)

## 3. 开放端口与验证

在服务商控制台的安全组/防火墙放行 **TCP 80**；使用 8080 时放行 8080。SSH 保留已有管理规则，数据库与宝塔管理端口不属于网站公开端口。若启用 UFW，先确保已有 SSH 规则，再放行网站端口；Docker 暴露端口可能绕过 UFW，公网入口应同时由云安全组控制。[Docker 防火墙说明](https://docs.docker.com/engine/install/ubuntu/#firewall-limitations)

在服务器测试：

```sh
curl -I http://134.195.211.122.sslip.io/
curl -I http://134.195.211.122.sslip.io/not-found
```

主站应为 200，不存在的地址应为 **404**。添加客户后再检查该客户子域名的页面与视频；视频 Range 请求应为 **206** 且包含 `Content-Range`。原生 Nginx 有多个站点时用实际公网 IP 测试，或在本地请求加入实际站点的 Host 头。

最后在自己电脑与手机流量网络上打开：

```text
http://134.195.211.122.sslip.io/
```

能打开网页、切换图片、拖动本地视频并下载 PDF 后，再把链接交付给客户。第三方 B 站/YouTube 视频能否嵌入取决于平台策略，作品集保留原片链接。

若连接失败：先看 `docker compose ps` 和日志，再确认端口、云安全组以及主机防火墙。不要用本机的 `127.0.0.1` 地址发给客户。

## 4. 更新与回退

Docker 部署：

```sh
cd Web
git status --short
git rev-parse HEAD
git pull --ff-only
sudo docker compose up -d --build
curl -f http://127.0.0.1/healthz
```

更新前保存上一步的提交 SHA，并确认服务器没有未提交的页面修改。文件在镜像内，更新代码后必须重新构建。运行 `docker compose logs --tail=100 web` 查看错误。

需要回退时，确认服务器工作区干净，再把 `旧提交SHA` 替换成保存的实际值：

```sh
git switch --detach 旧提交SHA
sudo docker compose up -d --build
```

恢复跟随主分支：`git switch main`，然后重新拉取、构建。宝塔/原生 Nginx 更新前备份网站目录，再上传新 `public/`；移除新版本已删除的旧页面时核对目标目录。

## 5. 购买域名后

1. 主域名、`www` 和 `*` 的 A 记录指向服务器公网 IP，`*` 提供客户子域名的泛解析。
2. 修改 `public/config.js` 的 `customerDomain`；修改 Nginx `map` 中的 `www` 域名、客户域名正则和 `server_name`。主域名与 `www` 显示主站，一级客户子域名直接对应客户目录。`www` 保留给主站，不作为客户名称。
3. Docker 部署可以继续在 127.0.0.1:8080 提供静态站，由宿主 Nginx/宝塔处理域名和证书。
4. 放行 TCP 443，在实际对外服务的 Nginx/宝塔中申请 HTTPS 证书。自己的主域名可通过 DNS 验证申请泛域名证书；sslip.io 临时域名应逐个申请证书，不能申请其泛域名证书。[sslip.io TLS 说明](https://nip.io/)

原生 Nginx 更新时，在 `/opt/dongshan-web` 执行 `git pull --ff-only`；页面文件直接被服务，Nginx 配置有变化时重新执行安装脚本。回退同样使用保存的旧提交 SHA，并恢复对应 Nginx 配置。

证书部署与自动续期按实际 Nginx/宝塔环境操作。[Certbot 官方 Nginx 指引](https://certbot.eff.org/instructions?ws=nginx&os=snap)

服务器在中国大陆时，正式绑定域名前核对服务商的备案与接入要求；规则取决于所在地、网站内容和服务商，具体部署时再核实。
