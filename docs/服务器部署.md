# 自有服务器部署指南

当前方案使用公网 IP 和客户目录；不需要先买域名。下列命令在**服务器终端**执行，本机预览在 Windows 项目目录执行。

## 1. 确认服务器状态

在云平台控制台打开远程终端，或在自己的终端通过 SSH 登录。先执行：

```sh
cat /etc/os-release
uname -m
command -v docker
command -v nginx
sudo ss -lntp | grep -E ':(80|443|8080)\b' || true
```

记录公网 IP、系统版本、所在地区、是否安装宝塔和是否已有网站。不要把密码、私钥或 GitHub 令牌写进仓库。

## 2A. 已安装 Docker 的服务器

Docker Compose 需要 `docker compose version` 可以正常运行。系统中没有 Docker 时，先按实际发行版安装；Ubuntu 22.04/24.04/26.04 可参照 [Docker 官方 Ubuntu 安装文档](https://docs.docker.com/engine/install/ubuntu/)。已有容器运行时先检查版本与冲突，不重复安装。

选择自己的工作目录，不覆盖已有项目：

```sh
git clone https://github.com/DongShan-Hu/Web.git
cd Web
cp .env.example .env
sudo docker compose version
sudo docker compose config
sudo docker compose up -d --build
sudo docker compose ps
curl -f http://127.0.0.1/healthz
```

仓库是公开仓库，克隆不需要 GitHub 密码。若服务器不能连接 GitHub，可在 GitHub 下载源码 ZIP 并上传、解压后进入项目目录；不需要改动服务器网络设置来完成部署。

80 被占用时，编辑 `.env` 改为 `WEB_PORT=8080` 后再启动，访问 `http://公网IP:8080/`。若通过现有宝塔/Nginx 反向代理，设为：

```dotenv
WEB_BIND_IP=127.0.0.1
WEB_PORT=8080
```

再把现有网站的代理目标设置为 `http://127.0.0.1:8080`。此时客户端访问现有网站端口，不需要将 8080 开放到公网。

Nginx 镜像固定为官方 `1.30.4-alpine`，源码与配置被构建进镜像。[官方镜像说明](https://hub.docker.com/_/nginx)

## 2B. 宝塔静态网站

1. 在宝塔中新建静态网站。没有域名时，在面板允许的范围内用公网 IP 建站，或将这个站点设为默认站点。
2. 将本项目 **`public/` 内的内容** 上传到网站根目录；不要上传整个仓库或原始素材目录。
3. 首页设为 `index.html`，保持 `sites/`、`assets/`、`media/` 的目录结构。纯静态网站不要添加 PHP 或 SPA 的全路径首页回退。
4. 启用 Nginx 静态服务，并配置 404 页面为根目录的 `404.html`。确认 MP4/PDF/WebP 的 MIME 类型正常。
5. 在云平台安全组和面板防火墙放行实际网站端口。

模板、文档、`.git/` 和 `.env` 不应放到网站根目录。主站地址为 `/`，作品集地址为 `/sites/zhang-hong/`。

## 2C. 原生 Nginx

适用于希望不用 Docker 的 Linux 服务器。安装 Nginx 的命令取决于发行版，例如 Ubuntu/Debian：

```sh
sudo apt update
sudo apt install nginx git
```

克隆仓库后，将 `public/` 内容复制到一个独立网站目录，例如 `/var/www/dongshan-web/`。Nginx 只需要网站文件，不需要 Node.js。

以 `deploy/nginx.conf` 为配置起点，并调整：

```nginx
listen 80;
listen [::]:80;
server_name 你的服务器公网IP;
root /var/www/dongshan-web;
```

把配置中的两处 `default_server` 删除，`server_name` 写成实际公网 IP，以免与已有默认站点冲突。原文件内的静态资源、Range、404、缓存规则可以保留。

Ubuntu/Debian 通常将配置放在 `/etc/nginx/sites-available/dongshan-web`，再链接到 `/etc/nginx/sites-enabled/`；其他发行版可能使用 `/etc/nginx/conf.d/`。已有网站时，不覆盖原有配置，也不删除现有默认站点。

```sh
sudo nginx -t
sudo systemctl reload nginx
```

只有语法检查通过才重载。Nginx 原生静态服务支持 MP4 Range 请求，不需要代理到 Node 服务。[Nginx 官方文档](https://nginx.org/en/docs/http/ngx_http_core_module.html)

## 3. 开放端口与验证

在服务商控制台的安全组/防火墙放行 **TCP 80**；使用 8080 时放行 8080。SSH 保留已有管理规则，数据库与宝塔管理端口不属于网站公开端口。若启用 UFW，先确保已有 SSH 规则，再放行网站端口；Docker 暴露端口可能绕过 UFW，公网入口应同时由云安全组控制。[Docker 防火墙说明](https://docs.docker.com/engine/install/ubuntu/#firewall-limitations)

在服务器测试：

```sh
curl -I http://127.0.0.1/
curl -I http://127.0.0.1/sites/zhang-hong/
curl --range 0-1023 -D - -o /dev/null http://127.0.0.1/sites/zhang-hong/media/tiangang.mp4
curl -I http://127.0.0.1/not-found
```

页面应为 200，视频请求应为 **206** 且包含 `Content-Range`，不存在的地址应为 **404**。原生 Nginx 有多个站点时用实际公网 IP 测试，或在本地请求加入实际站点的 Host 头。

最后在自己电脑与手机流量网络上打开：

```text
http://公网IP/
http://公网IP/sites/zhang-hong/
```

能打开网页、切换图片、拖动本地视频并下载 PDF 后，再把链接交付给客户。第三方 B 站/YouTube 视频能否嵌入取决于平台策略，作品集保留原片链接。

若连接失败：先看 `docker compose ps` 和日志，再确认端口、云安全组以及主机防火墙。不要用本机的 `127.0.0.1` 地址发给客户。

## 4. 更新与回退

Docker 部署：

```sh
cd Web
git status --short
git rev-parse HEAD
git pull --ff-only
sudo docker compose up -d --build
curl -f http://127.0.0.1/healthz
```

更新前保存上一步的提交 SHA，并确认服务器没有未提交的页面修改。文件在镜像内，更新代码后必须重新构建。运行 `docker compose logs --tail=100 web` 查看错误。

需要回退时，确认服务器工作区干净，再把 `旧提交SHA` 替换成保存的实际值：

```sh
git switch --detach 旧提交SHA
sudo docker compose up -d --build
```

恢复跟随主分支：`git switch main`，然后重新拉取、构建。宝塔/原生 Nginx 更新前备份网站目录，再上传新 `public/`；移除新版本已删除的旧页面时核对目标目录。

## 5. 购买域名后

1. 主域名和 `www` 的 A 记录指向服务器公网 IP。
2. 在实际对外服务的 Nginx/宝塔网站中填入域名，放行 TCP 443，申请并安装 HTTPS 证书。
3. Docker 部署可以继续在 127.0.0.1:8080 提供静态站，由宿主 Nginx/宝塔处理域名和证书。
4. 保留 `/sites/客户名称/` 路径。客户独立子域名也可单独配置 Nginx 的站点根目录；若使用此方案，请额外处理该子站的 404 页面路径。

证书部署与自动续期按实际 Nginx/宝塔环境操作。[Certbot 官方 Nginx 指引](https://certbot.eff.org/instructions?ws=nginx&os=snap)

服务器在中国大陆时，正式绑定域名前核对服务商的备案与接入要求；规则取决于所在地、网站内容和服务商，具体部署时再核实。
