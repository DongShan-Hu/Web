## 2. 当前 Cloudflare 安全配置

已完成或应保持的设置：

- DNS 记录使用橙色云朵代理。
- SSL/TLS 加密模式：`完全（严格） / Full (strict)`。
- 一定要用 HTTPS：开启。
- 自动 HTTPS 重写：开启。
- 最低 TLS 版本：`TLS 1.2`。
- TLS 1.3：开启。
- Universal SSL：保持启用。
- Cloudflare 免费管理规则集：保持“始终活跃”。
- HTTP DDoS 防护：保持“始终活跃”。
- 浏览器完整性检查：开启。
- 机器人对战模式：开启；若未来 API、自动化客户端或监控程序被误拦截，再检查安全事件并评估是否关闭。
- Under Attack Mode：平时关闭，只在网站正遭受明显攻击时临时开启。
- HSTS：暂时关闭，等所有计划使用的子域名都稳定支持 HTTPS 后再评估。
- ACM、Total TLS：当前不需要购买或开启。

DNSSEC 已提交启用后，Cloudflare Registrar 可能显示“等待中”。Cloudflare 会自动提交 DS 记录，通常需要数小时，最长可能需要一至两天。最终显示“活动/已确认”才算完成。

## 3. 日常从 GitHub 更新服务器

### 3.1 登录服务器

在 Windows PowerShell 中执行：

```powershell
ssh root@134.195.211.122
```

密码只在 SSH 终端中输入，不要发送到聊天、文档或 GitHub。

### 3.2 更新前检查

```bash
cd /home/dongshan/workspace/Web
git status --short
git branch --show-current
git remote get-url origin
git log -1 --oneline
```

当前服务器已知存在以下本地文件状态：

```text
 M public/config.js
?? public/config.js.bak-20260920-domain
```

这是域名切换时保留的配置和备份。不要执行 `git reset --hard`，不要直接删除。如果 GitHub 新提交也修改了 `public/config.js`，应停止更新并先合并配置。

### 3.3 先查看远端会修改哪些文件

```bash
git fetch origin main
git log --oneline HEAD..origin/main
git diff --name-status HEAD..origin/main
```

若远端没有修改服务器已有的本地修改文件，再执行：

```bash
git pull --ff-only origin main
```

`--ff-only` 可以避免服务器意外产生合并提交。拉取完成后确认：

```bash
git log -1 --oneline
git status --short
```

由于 Nginx 直接读取仓库中的 `public/`，静态文件拉取完成后通常立即生效，不需要重启 Nginx。

### 3.4 更新后检查

```bash
nginx -t
systemctl status nginx --no-pager

curl -I https://yiyeying.com/
curl -I https://huhaiyan.yiyeying.com/
curl -I https://zhanghong.yiyeying.com/
```

预期均返回 `200 OK`。浏览器仍显示旧内容时，先按 `Ctrl + F5` 强制刷新，再检查 Cloudflare 缓存。

## 4. Nginx 域名映射原理

Nginx 使用 `$host` 决定网站根目录。当前关键映射逻辑为：

```nginx
map $host $showcase_root {
    default /home/dongshan/workspace/Web/public;
    huhaiyan.yiyeying.com /home/dongshan/workspace/Web/public/sites/hu-haiyan;
    zhanghong.yiyeying.com /home/dongshan/workspace/Web/public/sites/zhang-hong;
    # 其余符合规则的一级子域名按同名目录查找。
}
```

胡海燕和张红需要显式映射，是因为公网主机名 `huhaiyan`、`zhanghong` 与目录名 `hu-haiyan`、`zhang-hong` 不完全相同。

修改 Nginx 后必须先检查，再重载：

```bash
nginx -t
systemctl reload nginx
```

只有看到下面两行才能重载：

```text
syntax is ok
test is successful
```

当前 Nginx 配置备份包括：

```text
/etc/nginx/conf.d/dongshan-web.conf.backup-20260920-portfolios
```

不要在未确认目标文件的情况下删除备份。

## 5. 新增一个作品集子域名

假设新增目录：

```text
public/sites/new-person/
```

计划使用：

```text
newperson.yiyeying.com
```

### 5.1 本地准备与 GitHub 同步

1. 将完整网站放到 `public/sites/new-person/`。
2. 在 `public/sites.json` 登记站点。
3. 本地运行检查：

```powershell
npm.cmd run check
```

4. 提交并推送到 GitHub。
5. 服务器按“日常从 GitHub 更新服务器”章节安全拉取。

### 5.2 添加 DNS

首次签发证书时，先创建灰色云朵记录：

| 类型 | 名称 | 内容 | 代理状态 |
| --- | --- | --- | --- |
| `A` | `newperson` | `134.195.211.122` | 仅 DNS，灰色云朵 |

确认解析直达服务器：

```powershell
nslookup newperson.yiyeying.com 1.1.1.1
```

此时应返回 `134.195.211.122`。

### 5.3 添加 Nginx 映射

如果子域名和目录名一致，例如 `new-person.yiyeying.com` 对应 `sites/new-person/`，通用正则可以直接处理。

如果子域名与目录名不同，例如 `newperson` 对应 `new-person`，需要在 `map` 中增加精确映射：

```nginx
newperson.yiyeying.com /home/dongshan/workspace/Web/public/sites/new-person;
```

然后执行：

```bash
nginx -t
systemctl reload nginx
```

### 5.4 扩展现有证书

扩展证书时必须完整列出已有域名和新增域名，防止意外移除旧域名。例如再增加 `newperson.yiyeying.com`：

```bash
certbot --nginx \
  --cert-name yiyeying.com \
  -d yiyeying.com \
  -d www.yiyeying.com \
  -d huhaiyan.yiyeying.com \
  -d zhanghong.yiyeying.com \
  -d newperson.yiyeying.com \
  --expand \
  --redirect \
  --no-eff-email
```

若 Certbot 显示：

```text
(U)pdate certificate/(C)ancel:
```

输入 `U`，不要输入邮箱。

证书成功后先直接验证：

```bash
curl -I https://newperson.yiyeying.com/
```

最后回到 Cloudflare，把 `newperson` 的 DNS 记录改成橙色云朵“已代理”，再从公网验证。

## 6. 故障判断

### 6.1 显示 “Welcome to nginx”

含义：DNS 已到服务器，但 Nginx 没有把该主机名映射到目标网站。

检查：

```bash
nginx -T 2>&1 | grep -n "server_name"
nginx -T 2>&1 | grep -n "showcase_root"
```

### 6.2 返回 404

检查目标目录和首页是否存在：

```bash
test -f /home/dongshan/workspace/Web/public/sites/hu-haiyan/index.html && echo ok
test -f /home/dongshan/workspace/Web/public/sites/zhang-hong/index.html && echo ok
```

再检查域名是否映射到了正确目录。

### 6.3 Cloudflare 526

含义：Cloudflare 使用 Full (strict) 连接源站时，源站证书无效或未包含当前主机名。

不要切换到 Flexible。检查证书包含的域名：

```bash
certbot certificates
```

如缺少新域名，按“扩展现有证书”章节重新签发。

### 6.4 Cloudflare 521/522

含义通常是源站 Nginx 未运行、端口未开放、防火墙阻挡或连接超时。

检查：

```bash
systemctl status nginx --no-pager
ss -lntp | grep -E ':80|:443'
```

### 6.5 HTTPS 正常但页面仍是旧内容

依次检查：

```bash
cd /home/dongshan/workspace/Web
git log -1 --oneline
curl -I https://目标域名/
```

然后浏览器按 `Ctrl + F5`，必要时再清除 Cloudflare 对应 URL 的缓存。

## 7. 重要禁区

- 不要把服务器密码、SSH 私钥、证书私钥或 GitHub Token 发到聊天或提交到仓库。
- 不要执行 `git reset --hard` 覆盖服务器未知修改。
- 不要在 `nginx -t` 失败时重载或重启 Nginx。
- 不要为二级作品集子域名额外添加 `www`，除非已经明确购买并配置对应的 Cloudflare 高级证书能力。
- 不要把 Cloudflare SSL/TLS 模式改成 Flexible。
- 不要随意开启 HSTS preload；错误配置可能让域名长时间无法恢复访问。
- 不要重复运行 `deploy/install-nginx-ubuntu.sh`。截至 2026-09-20，线上 Nginx 已经过 Certbot 和作品集映射手工扩展，该安装脚本可能覆盖现有 HTTPS 与域名映射。应先更新并验证仓库内的部署生成逻辑，再考虑重新执行。
- 不要只凭浏览器翻译后的 Cloudflare 名称判断 DNS，优先检查编辑框或实际 DNS 查询结果。
